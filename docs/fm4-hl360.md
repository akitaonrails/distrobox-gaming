# Forza Motorsport 4 — PC port (hl360-forza4)

[0herculabs/hl360-forza4](https://github.com/0herculabs/hl360-forza4) `v0.3.9`
is a native recompilation of the Xbox 360 game with ReXGlue, run through
GE-Proton. It **replaced `Alexbeav/fm4-recomp` on 2026-10-27**: that project
only ever accepted the *Europe* Game of the Year disc, while this one supports
the **USA Rev 1** play disc, and it ships an **SDL3/Dear ImGui launcher**
(no WebView2, so it works under Wine) with disc installation, Project Forza
Plus 4 support, wheel FFB and named profiles. v0.3.9 switched the renderer to
**Vulkan**, which fits this box's setup.

|---|---|
| Title ID | `4D530910` |
| Media ID | `33E7B39F` |
| XEX version | `0.0.0.14` |

Other regions and revisions are unvalidated by upstream and refused by its
installer (full-ISO MD5, then a SHA-256 manifest of the extracted files).

Upstream's Disc 1 MD5 is **redump disc 113180** — *Forza Motorsport 4 (Disc 1)
(Play Disc), USA, Rev 1, "Original, Racing Game of the Year Edition"*, PVD
2012-03-19, mastering ring **`33E7B39F`**, SHA-1
`271d91b2eab7aa719dcbf02799d9673b19aadef7`. So the "Racing Game of the Year"
re-release exists per region:

| Edition | redump | Disc 1 MD5 | inner ring |
|---|---|---|---|
| **USA Rev 1 (Racing GOTY) — what hl360 needs** | 113180 | `2470358250b8566bf5ddc3aaf1b76c68` | `33E7B39F` |
| EU Rev 1 (Racing GOTY) — old fm4-recomp wanted | 88560 | `90ff7a4c1cd7237bb455fc6aeb4081a6` | `42C67824` |

**Local status: verified.** The USA Rev 1 set (redump 113180/113181) lives in
`ROMS_FINAL/xbox360/x360-fm4-usa-rev-1/` and both MD5s match the table above, so
the game installs and runs. Four other FM4 images are on disk and are *not*
usable: USA original Disc 1 `cca0bf793e0e4086987359260054851e` (redump 79785) and
Disc 2 `f50603eec0b6c6e058d84539e35d51ef`, the Essentials Edition (different XEX
hashes) and the PAL original `046767384aacebe7e13cbe4a0cf9c3f0`. The role prints
this comparison on every run and installs only from the Rev 1 pair.

## Install

The role installs the port and stages the discs, but the game tree itself is
produced by the port's own `fm4tool.exe`, because upstream's launcher refuses to
extract when the NAS mount is in the way:

1. **Stage both ISOs locally.** `dg_hl360_disc1`/`dg_hl360_disc2` live on
   `/mnt/terachad` (NFS4). Extracting straight off that mount silently truncates
   files and mangles path case, so the role copies each image to
   `~/.local/share/../cache/hl360-fm4/fm4-disc{1,2}.iso` first and only ever
   reads from there.
2. **Disc 1** → `fm4tool iso <disc1.iso> …/FM4/game` (4,034 files, guarded by
   `creates: …/game/default.xex`).
3. **Disc 2** → `fm4tool iso <disc2.iso> …/disc2`, then
   `fm4tool install-dlc …/FM4/game …/disc2 …/user`, which registers the four
   licensed car/track packs (`4d5309100000000{1..4}` plus their headers) in the
   user root.

`fm4tool.exe` is a Windows binary: it only runs through the same GE-Proton
prefix as the game (`proton run ./fm4tool.exe …`, paths in `Z:\…` form). Plain
box Wine fails on the wineserver version mismatch.

## Run

Walker entry **Forza Motorsport 4 · PC Port** → `bin/fm4-port` → **`fm4.exe`
directly** under GE-Proton. The port's own launcher is *not* in the default path:
it keeps installation receipts that only it can write, and since Disc 1 was
extracted by the role it reports "Not installed" forever (and its Step 2/3 stay
disabled). Everything it would configure is already in `fm4.user.toml`, so
launching the game directly is both simpler and immune to that state machine.

`fm4-port --launcher` still opens the port's SDL3/ImGui UI when the launcher is
genuinely needed (wheel calibration, Forza Plus install/uninstall).

Player data (profiles, settings, logs, Disc 2 content) lives in
`~/.local/share/hl360-fm4`, symlinked into each release as `user/` and `logs/`,
so version bumps keep saves.

## Settings (`FM4/fm4.user.toml`)

The role seeds a validated baseline the first time a release is set up, then
keeps the keys it owns at those values on every run (the game rewrites the file
on exit, so **never edit it while the game runs**). Everything else in the file
stays whatever the player set:

- `game_data_root` / `user_data_root` name the versioned release directory and
  must follow a version bump;
- `mnk_mode = false`, otherwise keyboard/mouse mode steals the d-pad and left
  stick from the pad;
- the graphics baseline below — this exists because a launcher instance left
  open across an edit writes its own in-memory copy back on exit, which silently
  reverted aniso 16 → 5, async → on and readback → none once.

| Setting | Value | Why |
|---|---|---|
| `graphics_preset` / `resolution_scale` | 3 (Custom) / 4 | 4x = ~5K internal, downscaled to the 4K output |
| `anisotropic_override` | 16 | 16x AF |
| `present_effect` | `fsr` | cheapest clean upscale to 4K |
| `async_shader_compilation` | `false` | async skips draws while pipelines build |
| `readback_resolve` | `fast` | `none` drops resolves the game expects (roads, car thumbnails, mirrors) |
| `vsync` | `true` | this is the *guest vblank* pacing: off = 1000 Hz timer, not the game's 60 Hz |
| `host_present_fps_limit` | 60 | the game's own frame cap |
| `video_mode_*` | 1280×720 @ 60 | the mode asked *from the game*; output resolution comes from scale + window. Setting 4K here gives audio with no picture |
| `mnk_mode` | `false` | keyboard/mouse mode hijacks the d-pad and left stick |

Never set `video_mode_*` to the output resolution, and do not hand-edit the file
while playing: a still-open launcher writes its in-memory copy back on exit and
silently reverts every change made in between.

## Gamepad

The port asks **Windows.Gaming.Input** first. Wine's WGI enumerates the device
but never fires the `GamepadAdded` events the port waits for, so it reports no
pad at all (the same defect breaks GT2's gilrs path). The launcher therefore
runs with `WINEDLLOVERRIDES="windows.gaming.input=d"`, which makes the port use
its own SDL/XInput path — verified with an 8BitDo Ultimate 2 (`2dc8:310b`).

## Project Forza Plus 4

The community career/car mod (separate game copy and saves, `Normal`/`Hard`/
`Sandbox`/`Vanilla` chosen at install time) is installed by
`install-forza-plus.ps1` inside the release. It only touches Disc 2 packages
that already have headers and preserves the original executable and render
settings. Status: **not installed here.**

Two reasons, both worth knowing before retrying:

- The launcher's Installation tab gates Step 3 behind its own "Disc 1
  installed" receipt, which a role-extracted tree never has, so the button
  stays disabled. The script itself only needs `default.xex` in the game
  directory, so it can be driven directly.
- Step 3 shells out to `powershell`, and **the Proton prefix has no Windows
  PowerShell** (`drive_c/windows/system32` carries none, and GE-Proton does not
  add one), so installing it from the launcher inside Wine fails regardless.
  Run the script under PowerShell 7 for Windows instead:

  ```sh
  # PowerShell-7.6.9-win-x64.zip from the PowerShell releases, unzipped beside FM4/
  proton run pwsh.exe -NoProfile -File install-forza-plus.ps1 \
    -BaseZip 'Z:\…\cache\hl360-fm4\pfp4-v1.2.zip' \
    -UpdateZip 'Z:\…\cache\hl360-fm4\pfp4-v1.2-update.zip' \
    -GameDir 'Z:\…\FM4\game' -UserDir 'Z:\…\FM4\user' -Mode Sandbox
  ```

  It stages its own copy of Disc 1 plus the Disc 2 content (~8 GB) into
  `game/.fm4-plus` and `user/.fm4-plus` and writes SHA-256 receipts; `-Mode`
  cannot be changed afterwards without uninstalling and reinstalling (mod saves
  survive). Upstream validated Normal mode only.

## Not available

- **Marketplace DLC** (the car packs under
  `ROMS_FINAL/xbox360/Forza Motorsport 4 DLCs/`) cannot be installed. The port's
  content manager only understands the four Disc 2 packages; upstream issue #8
  ("Add possibility to install DLCs") is still open. The files stay on disk
  unused rather than being hand-rolled into the user root.
- **120 FPS mode** is experimental (needs a 120 Hz desktop; upstream warns of
  artifacts). 60 FPS is the supported target and the correct game speed.
- Xbox Live: no online, no marketplace, profiles are local.
